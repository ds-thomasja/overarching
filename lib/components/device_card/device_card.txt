h2. User Story

As a clinician selecting among several connected devices, I want to see each device's thumbnail, name, and some device specific informations summarized in a single card, so that I can identify and pick the right device at a glance.

----

h2. Design Definition & Assets

* *Figma Link:* [DeviceCard|https://www.figma.com/design/oY2AELOxR8s6HKYkCTAOQs/Equipment-Components?node-id=4837-19131]
* *Flutter Component:* [device_card.dart|https://github.com/ds-thomasja/overarching/blob/main/lib/components/device_card/device_card.dart]
* *Interaction Model:* The card is a single tap/keyboard-activatable surface. Tapping (or pressing Enter/Space while focused) fires {{onTap}}, but only when {{enabled == true}}, {{isLoading == false}}, and {{onTap != null}} — otherwise the card renders its visual state but does not respond to input. Where a tap navigates to, or what selecting the card is used for by the caller, is not defined by the component itself. {{selected}} is a purely visual flag driven by the caller; the card does not manage its own selection state or emit a selection-changed callback. {{isLoading}} puts the card into a non-interactive skeleton state without swapping to a separate placeholder layout — see Content Logic & Edge Cases.

h2. Component Props

|| Prop || Type || Default || Description ||
| {{name}} | String | required, no default | Primary device name/title; single line, ellipsis-truncated |
| {{subline}} | String? | null | Secondary line, e.g. a serial number ("SN:865562"); wraps up to 2 lines |
| {{thumbnail}} | Widget? | null | Widget rendered in the thumbnail slot; falls back to a plain {{var(--surface-subdued, #f5f5f5)}} placeholder box when omitted |
| {{batteryPercent}} | int? | null | Battery level 0–100; the battery indicator is hidden entirely when null |
| {{lowBatteryThreshold}} | int | 30 | At or below this battery level the battery icon switches to the critical color |
| {{status}} | DeviceCardStatus? | DeviceCardStatus.online | Connectivity tag shown below the subline/battery row; null hides the tags row entirely |
| {{selected}} | bool | false | Selected visual state |
| {{enabled}} | bool | true | Enabled/disabled visual state and interactivity gate |
| {{isLoading}} | bool | false | Puts the card into its skeleton loading state and disables interaction |
| {{onTap}} | VoidCallback? | null | Tap callback; null makes the card non-interactive (no hover/press/focus visuals, not keyboard-activatable) |
| {{focusNode}} | FocusNode? | null | {{Focus.focusNode}} passthrough |
| {{autofocus}} | bool | false | {{Focus.autofocus}} passthrough |
| {{width}} | double | 438 | Fixed card width |

{{DeviceCardStatus}} enum values: {{online}} (renders a success-styled "Online" tag), {{offline}} (renders a neutral-styled "Offline" tag).

h2. Acceptance Criteria

 - *Functional:*
 -- When {{status}} is null, or {{isLoading}} is true, no tags row renders at all
 -- When {{status == DeviceCardStatus.online}}, the tag renders text "Online" with success styling; when {{offline}}, "Offline" with neutral styling
 -- When {{batteryPercent}} is null, the battery indicator and its divider glyph are both absent
 -- When {{batteryPercent}} is set and the subline fits on a single line with room remaining, the "·" divider + battery indicator attach inline at the end of that line
 -- When the subline has wrapped onto a second line, or there isn't room on the (single) first line, the battery indicator renders alone on one additional line below, and the divider is not rendered at all — not merely hidden
 -- {{name}} truncates with an ellipsis after 1 line; {{subline}} truncates with an ellipsis after 2 lines — both via {{DSText}}, which also gives the full string a hover tooltip
 -- At or below {{lowBatteryThreshold}} (default 30), the battery icon switches to the critical/low-level color; the percentage text color is unaffected
 -- Tapping the card only fires {{onTap}} when {{enabled == true}} AND {{isLoading == false}} AND {{onTap != null}}
 -- When {{isLoading == true}}, the tags row and the battery indicator are both suppressed regardless of {{status}}/{{batteryPercent}}; {{name}}/{{subline}} instead render as skeleton bones sized from the real strings passed in
 -- {{thumbnail}} falls back to a plain {{var(--surface-subdued, #f5f5f5)}} placeholder box when omitted

 - *States:*
 -- Default (enabled, not selected, not loading): background {{var(--surface-standard, #ffffff)}}; border 1px {{var(--border-subdued, #ebebeb)}}
 -- Hover: background {{var(--surface-hovered, #ebebeb)}}; border unchanged
 -- Pressed: background {{var(--surface-pressed, #d7d7d7)}}; border unchanged
 -- Focus: border 2px {{var(--border-focused, #71a2fe)}}; background reverts to {{var(--surface-standard, #ffffff)}}
 -- Selected (resting): background {{var(--surface-selected-standard, #eaf5fa)}}; border unchanged (1px subdued)
 -- Selected + Hover: background {{var(--surface-selected-hovered, #d5ebf6)}}
 -- Selected + Pressed: background {{var(--surface-selected-pressed, #a8d5eb)}}
 -- Selected + Focus: border 2px {{var(--border-focused, #71a2fe)}}; background {{var(--surface-selected-standard, #eaf5fa)}}
 -- Disabled ({{enabled = false}}): card chrome (background/border) is identical to the Default/Selected-Default pairing above — disabled has no distinct card-chrome color of its own; the thumbnail, name/subline text block, battery group, and tags row each drop to {{var(--opacities-disabled, 0.4)}} opacity; name/subline additionally swap text color to {{var(--text-disabled, #8a8a8a)}}
 -- Loading ({{isLoading = true}}): {{DSSkeletonizer}} renders the real name/subline content as bones at full opacity; the tags row and battery indicator are hidden outright rather than boned (see Content Logic & Edge Cases); the thumbnail renders as a bone via {{DSSpaciousCard}}'s own image-slot skeleton support, keeping its normal {{border/radius/small}} corner

 - *A11y:*
 -- The whole card exposes {{Semantics(button: true, enabled: enabled, selected: selected)}} unconditionally — role/enabled/selected state is announced even while non-interactive (disabled or loading)
 -- Keyboard activation (Enter/Space) and mouse hover/press/focus visuals are provided by the underlying {{DSSpaciousCard}}
 -- The thumbnail is wrapped in {{ExcludeSemantics}} — decorative, conveys no information beyond {{name}}/{{subline}}, so it is not announced as an unlabeled image
 -- The "·" divider glyph is painted directly (not a child widget) and never enters the semantics tree

h2. Content Logic & Edge Cases

* *Inline vs. own-line battery placement:* The "· + battery" unit only ever attaches inline to the subline's first line, and only when there is room. A subline that has already wrapped onto a second line never gets an inline battery next to that second line, even if there would be room — the battery always drops to its own line below in that case, and the divider is omitted entirely (not merely hidden) whenever the battery doesn't sit inline.
* *No subline, battery present:* The battery indicator renders alone with no divider, since there is nothing to divide it from.
* *Static Figma loading mock vs. real skeleton behavior:* The Figma node's "Disabled + loading" frame shows fixed-width skeleton pills ({{Skeleton/Pill/Width/M}} = 96px for the name, {{Skeleton/Pill/Width/L}} = 144px for the subline) and a thumbnail bone at {{border/radius/standard}}. The built component does not reproduce these as static constants: {{DSSkeletonizer}} derives each bone's width/height from the actual {{name}}/{{subline}} strings passed while {{isLoading}}, so callers should pass representative (or last-known) text rather than empty strings; and the thumbnail bone keeps the card's real {{border/radius/small}} corner rather than the mockup's {{border/radius/standard}} — real component behavior wins over the static mockup per the widget's own source documentation.
* *Battery indicator has no built-in disabled/loading treatment:* {{DSBatteryIndicator}} exposes no disabled state and, as of {{lightning_core_ui v51.0.0}}, is not skeleton-aware (it neither wraps itself in the DS skeleton mechanism nor is listed among {{DSSkeletonizer}}'s supported widgets). The card works around this package gap by (a) wrapping it in a group {{Opacity}} for disabled dimming, and (b) hiding it outright while {{isLoading}}, rather than letting it render as sharp real content next to skeleton bones.
* *Tags row absent while loading:* Matches the Figma "Disabled + loading" variant, which renders no tags row at all — this holds regardless of whatever {{status}} was passed.
* *Interactivity gate:* The card is only tap/keyboard-interactive when {{enabled && !isLoading && onTap != null}}; otherwise it still renders the correct visual state for {{enabled}}/{{selected}}, but does not respond to input.
* *Thumbnail radius layering:* {{DSSpaciousCard}} clips its image slot with the card's own {{border/radius/standard}}; the thumbnail is clipped a second time, inside that, at the smaller {{border/radius/small}} — this double-clip is intentional and produces the corner the Figma node specifies for the thumbnail specifically (distinct from the card's own corner).
